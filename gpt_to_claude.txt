The current architecture

Right now you have two independent pieces.

Historical Data
        │
        ▼
Find Best Thresholds
        │
        ▼
Run Monte Carlo
        │
        ▼
Run Evaluator

The problem is...

The threshold finder and the evaluator are optimizing different things.

The threshold finder might say

Bear < -1.3%

Bull > +3.5%

because maybe that minimizes average prediction error.

Then the evaluator comes along and says

90% interval

Observed

82%

Meaning

The thresholds actually produced a poorly calibrated model.

I would merge them.

Instead think of it like this.

Candidate Thresholds

↓

Run Full Historical Backtest

↓

Evaluate Model Quality

↓

Keep Score

↓

Try Next Thresholds

↓

Repeat

↓

Choose Winner

Now you're no longer optimizing thresholds.

You're optimizing forecast quality.

That's a huge philosophical difference.

I would completely redefine the objective.

Instead of asking

"What Bear/Bull threshold looks best?"

Ask

"What thresholds make the Monte Carlo produce the best forecasts?"

Those are not necessarily the same thing.

I'd actually build a "Threshold Optimizer."

Pseudo-code

best_score = -inf

for bear_threshold in candidate_bear_values:

    for bull_threshold in candidate_bull_values:

        score = evaluate_model(
            bear_threshold,
            bull_threshold
        )

        if score > best_score:

            best_score = score
            best_thresholds = (...)

Notice

evaluate_model()

is now the optimization objective.

Exactly like machine learning.

One idea I absolutely love

I think you've stumbled into what could become the "training loop" for your entire forecasting engine.

Imagine this:

Now everything in your project can plug into this loop:

Different numbers of states (3 vs. 5 regimes)
Second-order vs. first-order state models

The optimization target never changes—only the candidate model does.

One refinement I'd make to your current threshold optimization

Instead of optimizing the thresholds to minimize prediction error alone, optimize them to produce the best calibrated forecasting engine.

For example, define an objective function like:

Overall Score =
    0.50 × Calibration Score
  + 0.30 × Assignment Probability Score
  + 0.20 × 1-Day Forecast Accuracy

(You can tune these weights later.)

This has an important consequence: the thresholds won't simply separate Bear/Flat/Bull regimes—they'll be chosen because they make the entire Monte Carlo engine perform best in historical walk-forward testing. That's a much stronger objective, and it naturally scales as you add more sophisticated features in the future. I think that's the architecture you'll be happiest with six months from now.
